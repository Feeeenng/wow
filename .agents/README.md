# 项目级 AI 上下文

本目录保存可由 Git 同步的项目级 AI 上下文，面向个人开发者在多台设备之间恢复工作状态。它不依赖数据库或云服务，也不替代 AI 客户端自身的原始会话数据库。

## 文件职责

- `CONTEXT.md`：长期稳定的项目事实、用户偏好、约束和关键决策。
- `HANDOFF.md`：当前工作状态、最近完成事项、阻塞项和下一步；新设备优先读取。
- `INDEX.md`：历史记录索引，用于按主题和月份定位记录。
- `conversations/<年份>/<年月>.md`：按月保存结构化对话历史。

## 恢复顺序

1. 读取根目录 `AGENTS.md` 和 `CLAUDE.md`。
2. 读取 `CONTEXT.md`，恢复长期约束。
3. 读取 `HANDOFF.md`，恢复当前进度。
4. 只有需要追溯原因或旧决定时，才通过 `INDEX.md` 定位相关历史文件。

不得在每次任务开始时加载全部历史文件，否则历史增长后会浪费上下文窗口并降低有效信息密度。

## 写入规则

每次对话任务结束前执行以下维护：

1. 将新增长期事实或决定合并到 `CONTEXT.md`，避免重复堆叠。
2. 用最新状态覆盖 `HANDOFF.md` 中相应内容，使其始终代表当前状态。
3. 向当月历史文件追加一条记录，包含用户目标、关键讨论、决定、处理结果、验证和未决事项。
4. 仅在新建历史文件、增加分卷或主题索引发生变化时更新 `INDEX.md`。

历史记录使用 `Asia/Shanghai` 日期，采用以下格式：

```markdown
## YYYY-MM-DD：主题

- 用户目标：
- 关键讨论：
- 决定：
- 处理结果：
- 验证：
- 未决事项：
```

不要求逐字转录聊天。结构化摘要应保留以后理解决定和继续工作的必要信息，同时删除寒暄、重复内容和无长期价值的过程信息。

## 分片与归档

- 默认每月一个文件，路径为 `conversations/<年份>/<年月>.md`。
- 单个文件超过 200 KB 时，从下一条记录开始创建 `conversations/<年份>/<年月>-02.md`；后续分卷依次递增。
- 历史文件只追加或修正事实，不把多年记录合并成单一文件。
- 每年结束后保留原有年度目录，不做额外压缩；Git 已负责版本存储和增量同步。
- `CONTEXT.md` 和 `HANDOFF.md` 应保持精炼。失效内容应删除或替换，必要的历史原因留在月度记录中。

## 多设备使用

- 开始工作前先执行 `git pull`，结束工作后提交并推送 `.agents/` 的变更。
- 避免在多台设备上同时追加同一个月度文件；发生冲突时按时间顺序保留双方有效记录。
- `.agents/` 必须纳入 Git，不得加入 `.gitignore`。

## 安全边界

不得记录访问令牌、密码、私钥、真实环境变量、个人隐私、思维过程或大段命令输出。涉及敏感配置时只记录配置项名称、用途和安全的占位说明。
