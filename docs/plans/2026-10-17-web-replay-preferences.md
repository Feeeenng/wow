# Web个人回放偏好持久化方案

日期：2026-10-17（Asia/Shanghai）。状态：用户已明确授权并完成实现及隔离验证，证据见[个人偏好验证](../research/web-preferences-validation-2026-10-17.md)；尚未执行正式生产迁移。

## 问题与边界

当前Web偏好仅当前账号工作台内存，刷新后丢失；既有后端users／team_members没有用户偏好字段。桌面继续由Rust LocalStateStore保存，不修改其持久化路径，不使用浏览器localStorage。不得把个人设置塞进共享Recording.manifest、团队标注、令牌label或Redis最终状态。

目标是按平台账号及团队保存个人轨道、显示覆盖、轨高、图标比例和缩放；不保存令牌、连接、媒体播放／直播状态、原始事件或文件。不同团队和用户独立，删除成员关系清理该团队个人布局。其他成员即使团长也不能读取或代写。

## 数据与接口

拟新增第五版Alembic迁移，创建replay_preferences：user_id和team_id为联合主键，同时外键指向team_members(user_id,team_id)的对应列，成员删除时级联；version为0至4294967295的BIGINT，document为受严格契约约束的JSONB，updated_at为带时区时间。无历史业务行回填，无视频／事件表修改；降级仅删除此个人偏好表。

接口：GET与PUT /api/v1/teams/{team_id}/preferences/replay。平台身份只来自当前认证Principal，不接受请求中的user_id。先校验当前成员关系再读／写本人行，写入期间锁成员关系，与撤权保持顺序。

GET无行返回version=0及默认布局，不因读取插入行。PUT提交expectedVersion和完整document；先按相同联合键补空行，再以version条件原子CAS更新，一个并发请求成功、另一个409。返回服务端实际快照；版本上限拒绝，不静默覆盖。仅个人偏好，不需要leader角色。

document字段：

| 字段 | 约束 |
|---|---|
| customTimelineTracks | 至多8项，id为custom-加UUID；名称1至32个Unicode字符、去首尾空白、拒绝控制字符及忽略大小写重名 |
| timelineTrackOverrides | 至多1024条、每键至多160字符，与现有Rust边界一致；来源／技能／类型／真实来源身份生成键，目标仅五条默认轨道或当前个人轨道，拒绝悬空目标、控制字符及原型污染键 |
| timelineTrackHeight | 整数20至50，默认30 |
| timelineIconPercent | 整数50至100，默认80 |
| timelineZoom | 1至4且按0.5递增，默认1 |

JSON大小、规则数量和键长度由后端集中配置限制；前端使用同一业务边界。默认轨道为boss／player／team／aura／death，不改原事件归属。删除轨道同时移除指向它的显示规则；拖回默认轨道移除相应覆盖。

## 前端与失败行为

应用级账号Provider按团队缓存快照和未保存草稿，团队页卸载后保留；退出立即销毁，迟到响应不能写入新账号。读取失败显示错误及重试，不能用空默认值自动覆盖服务器。显式“保存个人布局”才PUT成功落盘，失败／409保留草稿和原版本；“读取最新”在有草稿时先确认替换。

读取期间可继续播放；个人布局变化及保存不重建播放器，不修改事件集合、时间映射、共享校准或团队标注。冲突后不自动重试覆盖别的浏览器修改。偏好保存不要求上传录像，也不自动发送本地日志。

## 必须验证

- PostgreSQL真实CAS并发一次200／一次409；无行GET无写入，非法名称／目标／数量／NaN／类型拒绝，未授权及其他用户隔离、撤权竞态。
- Web新增／改名／删除／清除／恢复、真实拖动及键盘等价操作，分组中不同规则不混改；事件JSON及定位不变。
- 当前用户刷新／重新登录从真实服务恢复；同团队另一账号不继承，切团队／迟到响应不串状态；保存失败／冲突保留草稿，读取最新需明确确认。
- 完整迁移升级／降级及重升级；原始录像／日志不写入、不上传，当前录制／媒体／事件链路回归。
