# 真实战斗技能图标覆盖验证（2026-10-17）

## 结论

随包技能资料从 13 项扩充到 1029 项，包含 741 张可离线读取的真实 JPEG。对用户指定目录中 17 个已唯一关联日志的录像，从完整战斗字节区间提取所选原始事件的技能展示字段，得到 1036 个不同技能。

公开资料链路成功提供其中 1025 个技能的图标，仍有 11 项明确缺图。这是当前真实样本的覆盖率，不能解释为全游戏覆盖率。时间轴优先使用 CombatLog 中文名称，资料包不修改时间、人物或事件来源。

## 资料链路与边界

1. 从既有只读审计的 17 个完整战斗字节区间提取技能 ID、名称及出现次数，不提取人物身份或账号资料。
2. 读取 [Wago 公开 SpellMisc CSV](https://wago.tools/db2/SpellMisc/csv?build=12.1.5.70391)，按 `SpellID` 关联 `SpellIconFileDataID`，优先通用难度 0。1036 项均有 FileDataID。
3. 使用 [wowdev 已验证文件名发布包](https://github.com/wowdev/wow-listfile/releases/tag/202610152328)，将 FileDataID 关联到 `interface/icons/*.blp` 路径。1035 项可查到已验证名称，未使用社区猜测清单。[两类清单的区别](https://github.com/wowdev/wow-listfile#verified-listfile)
4. 按已验证 basename 从 RPGLogs 固定图片源获取 JPEG。真实文件名含空格时编码 URL，本地使用 `filedataid_<FileDataID>.jpg` 安全别名；没有通过删空格猜测远端文件名，也没有放宽运行时路径校验。
5. 对缺失图片另做一次 Wowhead 固定图片 CDN 检查；仍未通过的资源不收录、不反复请求，也不改变运行时固定网络来源。

日志仅声明 `BUILD_VERSION=12.1.5`，没有完整构建号。可确认与资料版本系列相符，不能从日志证明细构建号为 `70391`。未导入旧版技能数值、描述或模拟规则。

REA 既有证据显示 ReviewTool 从 Encounter、友方技能和报告资料获取 `{name,icon}`，安装包提取清单没有全量离线图库。本次沿用已保存证据和[既有研究](reviewtool-timeline-seek.md)，没有重新运行目标或读取登录缓存；资料来自独立公开源，没有复制目标业务代码。

## 覆盖分母

匿名清单共 1361885 条原始 SPELL 记录；已提供图标的技能关联 1346938 条。筛选类型为：施法开始／成功，光环应用／移除／增加叠层／减少叠层／刷新，打断，驱散，复活，蓄力开始／结束／中断。

此清单在完整战斗字节区间内只按原始事件类型筛选，未应用生产时间轴的友敌、人物及事件可展示性过滤。因此它与 Rust `timelineEvents` 的计数不是同一指标，不能用这个分母宣称生产索引所有事件都已覆盖。死亡记录不含可用技能 ID，不纳入技能图标覆盖分母。

## 验证与复现

`client/tests/build-spell-resources.py` 读取显式指定的匿名技能清单、SpellMisc、已验证文件名和 GitHub 发布元数据，核对完整输入身份后生成资料。默认只读取已有图片，增加 `--download` 才进行固定源下载；不打开原日志或账号缓存。

```powershell
python client/tests/build-spell-resources.py `
  --inventory "$env:TEMP\wow-replay-phase2-20261017\real-spell-inventory.json" `
  --spellmisc "$env:TEMP\wow-replay-phase2-20261017\spellmisc.csv" `
  --listfile "$env:TEMP\wow-replay-phase2-20261017\verified-listfile.complete.csv" `
  --release "$env:TEMP\wow-replay-phase2-20261017\listfile-release.json" `
  --build 12.1.5.70391 --output client/src-tauri/resources/game-data
```

实际执行生成器并完成离线重建，退出码 0。实际执行 `node --test tests/runtime-assets.test.cjs`，3 项通过、0 失败、退出码 0，覆盖逐文件 SHA、图片头、ID 唯一性、来源映射、缺失清单一致性及 2MB 资料导入上限。

用本机已有 Pillow 对全部 741 张 JPEG 实际加载解码，0 个失败；731 张为 56×56，10 张为 64×64，没有新增 Python 依赖。

随后执行独立标识的真实 Tauri／WebView2 验收，11 项全部通过、退出码 0：1029 项技能分批调用真实原生查询成功；740 张当前技能引用图片与 1 张保留的初始图片，共 741 张通过原生图片协议实际读取，逐个 SHA-256 全部匹配资源清单；513 项超限查询被拒绝。没有将 IPC 或本地协议替换为 mock。

首次增加全图校验时，测试错误地假设“当前引用图片数”等于“保留资源文件数”，因 740 与 741 的差异失败。保留的旧图为 `spell_nature_healingwavegreater.jpg`，治疗链的新资料引用已变化；修正测试分别核对当前引用和全部资源后，完整 11 项通过。首次失败报告保留在原生临时证据目录，未删除失败记录。

原生验收还实际导入三场用户录像、完成事件查询和 HLS 播放。详细命令与边界见 [原生验证报告](replay-native-validation-2026-10-17.md)。这些证据证明资源完整性和实际加载路径；不等于全游戏资料覆盖，也不证明所有实战画面与日志都已达到 500ms 对齐目标。
