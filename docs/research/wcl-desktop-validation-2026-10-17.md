# WCL 标准事件桌面接入验证

日期：2026-10-17，时区：Asia/Shanghai。

团队回放增加“标准事件”面板，读取服务端配置及平台角色，显式提交公开报告代码、fight 和录像人物绑定。输入可以是官方 HTTPS 报告链接，客户端只提取报告身份，不请求用户输入的任意网址；WCL 应用凭证只存在服务端。私有和未列出报告明确暂不支持。

录像就绪与标准事件发布相互独立；没有完整事件时显示等待。导入期间仅在面板打开时轮询，失败保留旧发布版本，并分别说明请求和已发布报告。Rust 根据当前连接、团队和录像读取签名分页，令牌不进入网页；事件使用有符号共同战斗时间，独立于本地 u64 日志事件契约。

WCL actor 不冒充游戏 GUID；界面以报告命名空间与 actor 编号区分同名人物，筛选和拖轨分别保留身份。只显示共同战斗范围内的事件，原始前后事实保持不变。事件轨道属于个人显示规则，不修改服务端 owner 或事件时间。

实际验证：

- npm run build 退出码 0；当前构建 4943 模块，保留已有大 chunk 提示。
- node tests/browser-wcl-report.cjs --fixture <合成媒体目录> --output <本轮证据目录> --playwright <本机已有 playwright-core>：最新构建退出码 0，7 项通过，pageErrors 为空。
- 纯函数覆盖同名 actor 的独立键、真实 GUID 优先，以及外域、伪域名、HTTP、嵌入凭证和非法 fight 拒绝。
- Rust 标准事件保持负时间及环境 actor -1，状态接受数值报告 revision 与可空 actor 类型；相应定向用例由云端测试覆盖。
- 真实原生全栈报告已完成 10 项，包括 PG／MinIO／Redis／独立 Celery、上传进程恢复、两路共同零点、标准事件分页和点击、失败保旧与版本切换、平台降权／撤权，以及鼠标新增／拖动／重启恢复／删除个人轨道。详细证据见 [云端原生验证](cloud-client-validation-2026-10-17.md)。
